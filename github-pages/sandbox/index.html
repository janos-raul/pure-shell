Sandbox

Last updated: November 21, 2026

The Sandbox is a free, throwaway Linux shell. Use it to try Pure-Shell, or any SSH client, without a server of your own.

How to connect

In Pure-Shell 1.2 and later: see Help → Try the test server (Sandbox). In older versions, add it as a host yourself:

  1. Create a new key and name it Sandbox. Use it only for the Sandbox, not your real key.
  2. Add a host: hostname sandbox.pure-shell.eu, port 2222, any username (for example user), and log in with the Sandbox key.
  3. On the first connection, compare the fingerprint the server shows with the one below before you choose Trust.

With a normal OpenSSH client: any key works, and any username:

ssh -p 2222 anyname@sandbox.pure-shell.eu

Your key is your identity here. There are no accounts and no passwords; password login is refused.

Check the host key

The first time you connect, your client shows the server's fingerprint. It should match this one (ED25519):

SHA256:w7eazsZJSDUIJe9Uc4ZHQwObHy35liw5+RuOfbbCIWs

If it does not, do not continue. You can also check it before connecting:

ssh-keyscan -t ed25519 -p 2222 sandbox.pure-shell.eu | ssh-keygen -lf -

What to expect

  • Every login gets a fresh, empty container. Everything is deleted when you log out.
  • Sessions end after 30 minutes.
  • Sessions are recorded (including what you type) and kept up to 14 days, see Privacy. Abuse means a ban.
  • There is no internet access from inside, no port or agent forwarding, and no SFTP or file transfer.
  • Memory, processes and disk space are small, and the system is read-only. Only a small scratch area (like /tmp) is writable.
  • One session per IP address. A laptop and a phone on the same home Wi-Fi share one address, so close one session before opening the other.
  • Too many connection attempts in a short time lead to a short temporary block. Wait a few seconds and try again.

If the connection is refused with a message about the key (for example “Server rejected the key”) and your key is fine, you most likely already have a session open from the same address.

Rules

  • No attacks, no mining, no abuse of any kind.
  • Access can be removed at any time, without notice.
  • The Sandbox is provided as it is, with no promise that it is always up.
